# 04 · 上云与副本治理

> 目标：**云端恒 1 份**（同名课件不堆积、不撞车）。
> 铁律：**任何删除之前，先把候选清单摆给用户勾选，用户点"删"才删，没勾的一律留。**

---

## 一、副本为什么会堆积（根因）

```
本地 enbx → os.startfile 打开 → sync_current_courseware
```

**每次都新建一份 remoteId**。即使把 `<UpstreamId>` 写成旧记录（"派生自"语义），同步时**仍然新建** ⇒ 此路不通。

⇒ 结论：**不能靠"更新"覆盖，只能"先删旧、再上传"。**

---

## 二、🔒 删除前置确认闸门（用户拍板，脚本不自作主张）

**适用范围**：云端同名副本清理、本地废料清理、任何 `rm` / 云删除动作。

### 固定三段式：扫描 → 勾选 → 执行

```
① 扫描（dry-run，只读不删）
   脚本扫出全部候选，输出 JSON 清单：
   [ {id, 名称, 页数/大小, 创建时间, 删除理由, 建议: 删/留} ]
        │
        ▼
② 用户勾选（Agent 用 AskUserQuestion 多选呈现）
   用户逐条选"删 / 留"；没选的一律当"留"。
   可选保护名单 never_delete（如正在对比的旧版、别人共享的课件）。
        │
        ▼
③ 执行（只删用户勾过的）
   脚本读勾选结果，逐个执行；每删一个回报结果；
   任一失败立即停，不继续。
```

### 硬规则

1. **默认全留**：脚本不带参数时**绝不删**，只打印清单。
2. **选择即授权**：只有显式传入确认开关才动手；不带确认 = 全部保留。
3. **建议 ≠ 执行**：清单里的"建议删/留"只是给用户参考，脚本**不按建议自动执行**。
4. **保护名单**：`SEEWO_NEVER_DELETE`（逗号分隔）或 `scripts/never_delete.txt`（每行一个），命中即拒绝删除。
5. **一次一批 + 逐条回报**：任一删除失败 → 停止并报告，不静默跳过。
6. **可恢复优先**：云端删除是**进回收站**（可恢复）；本地删除优先走回收站机制，不用 `rm -f`。

### 云端副本清理的候选判定（供"建议"列用）

| 情形 | 建议 | 说明 |
|---|---|---|
| 与本次 build 同名、且是本地产物的旧副本 | **删** | 典型堆积副本 |
| 1 页废稿 / 空壳记录 | **删** | 测试残留 |
| 与本次同名但**页数/结构明显不同**（独立版本、有意并存） | **留** | 如第7课"新旧版并存" |
| 名称相似但非本课（邻课/共享） | **留** | 别误伤 |

### ✅ 落实处（2026-10-12 已实现）

`publish_courseware.py` 的 `--cleanup` **已升级为闸门制**（不再是"无脑删同名"）：

```bash
python scripts/publish_courseware.py "<enbx>" --cleanup          # ① 只扫描，列候选（不删、也不上传）
#      ↑ 输出"待删候选"清单 + 闸门提示框，然后**退出**
python scripts/publish_courseware.py "<enbx>" --cleanup --yes    # ② 确认后才删同名副本 → 再上传（云端恒 1 份）
python scripts/publish_courseware.py --clean "<课件名>"           # 只删指定课件（进回收站），不发布
```

- **未加 `--yes` 时只扫描：既删不了、也不会继续上传**（避免"没删干净又叠一份"）。
- Agent 侧配合：先把扫描清单用 `AskUserQuestion` 摆给用户勾选，用户点"删"后再带 `--yes` 重跑。
- ⚠️ **按 id 逐条删暂时做不到**：GUI 删除器（`_del_batch4.ps1`）是**按课件名**匹配列表行的，不支持只删某一个 `localId`。
  需要"留一部分"时，按**名字**区分（`--clean <名>`）——这也意味着同名副本只能整体删或整体留。

## 三、可行方案：`publish_courseware.py`（已跑通）

固定 5 步（第 1–3 步仅在带 `--cleanup` 时执行，且第 3 步需 `--yes`）：

1. **扫描**云端同名副本（只读，列候选）—— 不带 `--yes` 到此为止
2. 关闭同名 shell
3. **GUI 删除云端同名旧副本**（进回收站，可恢复）—— 须带 `--yes`
4. `os.startfile` 打开本地课件并等待就绪（等元素齐全且**连续两次一致**）
5. `sync_current_courseware` + **复查份数**

结果：**云端恒为 1 份**。在 `seewo_build.py` 里由 `--publish` 触发（`publish.cleanup=true`）。

## 四、⚠️ 云课件列表的 3 个致命细节（不知道就一定失败）

驱动客户端 GUI（UIAutomation）删云课件时，这三条缺一不可：

1. **列表行名带前缀** `[课件]` / `[课件组]` ⇒ `FindItemByProperty` 必须拼 `rowPrefix="[课件]"`，
   否则**静默 0 删除**（不报错，什么都不干）。
2. **确认弹窗正文是「30天内可在 … 找回」**，"回收站"三字是**独立超链接节点**（不在 Text 控件里）
   ⇒ 守卫词必须用 `30天内可在`（用「回收站」永远失配）。
3. **列表是缓存快照** ⇒ 必须先点 `RefreshButton`，否则刚上传的记录 `FindItemByProperty` 找不到、
   在 GUI 里**完全不显示**（记录像"隐形"了一样）。

## 五、其他 GUI 删除的坑

- **`.ps1` 必须纯 ASCII**：文件无 BOM ⇒ PowerShell 5.1 按 ANSI/GBK 解码 ⇒ 中文注释导致
  `ParserError` —— **不报错、不执行、返回空 trace**。中文目标名放 `$env:TEMP\*.json` 读入。
- **列表虚拟化**：用 `ItemContainerPattern.FindItemByProperty` + `ScrollIntoView`；
  **别用第 0 行的 BoundingRectangle**（首行坐标常偏出可视区，右键打空）。
- **右键位置**：`SetForegroundWindow` + `ShowWindow(h,3)` 最大化 → 右键**行中心偏左 `x+400`**。
- **没有删除接口**：MCP 61 个工具只有 `delete_slide` / `delete_elements`，**删云课件只能走 GUI**。
- **偶发 `FAIL no menu`**（窗口未前置）⇒ **重跑一次通常即成功**。
