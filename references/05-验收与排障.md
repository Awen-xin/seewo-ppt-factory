## 一、`_verify_v2.py`：本地 vs 云端逐页核验

```bash
"<PY>" _verify_v2.py "<本地 enbx>" "<云端缓存目录>"
```

- **本地**：把 enbx 当 zip 解压。
- **云端缓存目录**：`%APPDATA%\Seewo\EasiNote5\Data\<你的希沃账号>\Courseware\<localId>\`
  （注意这层目录用 `Board_*.xml` 而非 `Board.xml`，且 `Slide_*.xml` 在根下、**没有 `Slides/` 子目录**）。
- 逐页比对：元素数 / 标签 / 文字 / 动画（类别·触发·类型·步号）/ Group 内子元素数 / Orders 块 / 视频 / 活动。

**通过标准**：差异页 = 0，动画本地/云端数量一致。
（第6课 15/15、第7课 16/16 与 38/38、第8课 16/16 与 34/34 均通过。）

## 二、🔴 "页码整体错位"的真相（最常见误判）

客户端缓存文件名是 `Slide_<N>_<stamp>.<rand>.xml` ⇒ 按**文件名字典序**排会变成
`Slide_0, Slide_1, Slide_10, Slide_11, …` ⇒ 页码全乱，**看起来像"动画全部错位"**。

**正解**：读 `Board_*.xml` 的 `<Item>` 顺序对齐；或按文件名里的数字 N 排（N 从 0 起 = 第 N+1 页）。
`_verify_v2.py` 已按 Board 页序对齐。

排障提示：怀疑课件坏了时先跑 `_open_check.py`（**只打开、不同步** ⇒ 不产生云端副本），报 `slideCount`。
原版正常、探针只有 1 页 ⇒ 是内容问题，不是 XML 语法问题。

## 三、截图必须传绝对路径

截图由**客户端进程**落盘，按它自己的 CWD 解析相对路径 ⇒ **静默失败**（目录空、无报错）。
`expectedPngImageFilePath` 一律传绝对路径（`actualFilePath` 会回显真实落点）。

## 四、Group 子元素计数差异 = 良性（已知）

现象：核验时个别页报 `group_children` 计数不同（如第8课 P6 本地 `[4,4,4,6]` / 云端 `[5,5,5,6]`）。

根因（已用脚本逐组比对文字确认）：**云端客户端重存时，把 Group 的空容器 `Shape`（无文字无图片的装饰背景框）也计入了组内**，
本地落稿时该 Shape 不在组内。**内容文字、动画、元素数、Orders 块、视频/活动标记全部一致** ⇒ 不影响呈现，**判良性**。

> 判定脚本思路：复用 `_verify_v2` 的 `ordered_pages/split_top`，对每页每个 `<Group>` 提取子元素（tag + 文字/名称）逐条比对。

## 五、客户端缓存目录速查

```
%APPDATA%\Seewo\EasiNote5\Data\<账号>\Courseware\<localId>\
    ├─ <localId>.json                     课件元信息（含 remoteId 等）
    ├─ Board_<stamp>.<rand>.xml           ← 页序真相（<Item> 列表）
    ├─ Slide_<N>_<stamp>.<rand>.xml       ← 每页（N 从 0 起）
    ├─ Document_*.xml / Reference_*.xml / SaveInfoMetadataFile_*.xml
    ├─ thumbnail_*.png
    └─ <hash>_<stamp>.<rand>.<ext>        资源（图片/视频）
```
`CoursewareCacheData.db`（同级目录）是 SQLite，记 LocalId/RemoteId/LocalRevision/SyncedRevision。
